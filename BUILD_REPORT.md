## What was built (~/workspace/agent-army/builds/rebuild_adforge/app/)

FastAPI + Jinja2 + SQLite (stdlib), matching ChurnClinic's conventions
(config.py env-only + stub mode, render.yaml with sync:false env vars,
email-capture fallback pricing pattern):

1. **Landing page** — sells the product: hero with CSS 9:16 phone/storyboard
   mock, 4-step forge process, the 3 hook styles, honest-math CTA.
   Dark forge theme (the original's identity), zero external assets.
2. **Pricing page** — all 4 tiers. Each paid tier renders a live Stripe
   checkout button ONLY when its Payment Link env var is set; otherwise it
   renders an email notify-me form (captured to the leads table) — the exact
   ChurnClinic fallback pattern. Checkout clicks go through `/checkout/{tier}`,
   which logs a `checkout_click` event before 302ing to Stripe.
3. **Studio (create flow)** — product name, description, audience, offer,
   URL, email → generates the full ad package and saves it:
   - 3 hook options (one per style) with the first-3-seconds line + rationale
   - A complete timed shooting script **per hook** (HOOK/PROBLEM/DEMO/OFFER/CTA
     scenes: voiceover, visual direction, on-screen text)
   - Scene-by-scene shot list with camera directions
   - Caption sequence + hashtag pack
   - Package gets a permanent URL (`/package/{id}`)
   - Free-tier gate: 3 packages per email, then an upgrade prompt
     (soft gate — see Limitations)
4. **Gallery** — public sample packages generated by the same engine
   (Red Demon Tee, Portable Blender, Key Tracker) — no hand-written fakes.
5. **Video provider adapter** (`video_provider.py`) — env-configured HTTP
   contract (POST package JSON + Bearer key → job_id/video_url).
   **Stub mode by default**: returns "storyboard" status with an honest
   explanation; the package is still the full shoot-ready deliverable.
   Provider errors are caught — package saves, user sees a status note.
6. **Analytics** — SQLite `events` table + `log_event()` on page views,
   package creation, checkout clicks, lead captures, gate hits;
   **GET /api/stats** returns counts. Same lightweight pattern as the
   other Army web apps. No third-party tracker.
7. **/success** post-checkout page, **/health** probe, 404 handling.

## What's stubbed / honest limitations

- **No MP4 rendering.** Stub mode delivers the shoot-ready package
  (script + shot list + captions). This matches the ORIGINAL's real state —
  the Emergent version also never exported MP4s (storyboard preview only,
  per its own PRD backlog). A real render needs the video API plugged in.
- **Script generation is a deterministic template engine**, not an LLM.
  Templates are the original's three proven hook structures filled with the
  seller's product facts. Fast, consistent, $0 — but not free-form AI copy.
  Occasional template phrasing is slightly mechanical.
- **No user accounts/auth.** The original had JWT auth; this rebuild tracks
  packages by optional email instead. Consequence: the free-tier gate is
  **soft** (email-based, trivially bypassed) and paid-tier allowances are
  not enforced per user. Real accounts + a Stripe webhook are the fix —
  same backlog the original carried.
- **No URL scraping.** The original scraped Shopify/AliExpress links; this
  rebuild takes the product description directly (URL field is stored for
  reference). Scraping is a clean add-on later.
- **No TTS voiceover.** Depended on Emergent's integrations; returns when a
  provider is configured.
- **Payments are Payment Links only** (by design): no card data touches the
  app, no Stripe secret keys in code — same as ChurnClinic's Pro checkout.
